## 3. Technical contracts closed

### D09: integrity, attestation, intent and applicability

Architecture report:301–310 hashes planner/policy/codec versions yet falsely says all inputs are header columns; its proposed header:126–140 omits them. **Minimum correction:** `request_digest` hashes exactly header identity `(draft_session_id,workflow_run_id,plan_generation,round_index)`, `task_count`, frozen `parallel_limit`, `plan_digest`, `base_version_seq`, `base_data_hash`. Every input is a named header column in [DBML round table](../../db.dbml); JCS UTF-8, UUID canonical lowercase, integer canonical decimal, explicit fields, prefix `sf06:req:v2:` and SHA-256 with `merlink.sf06.request.v2\0` domain bytes. `plan_digest` separately hashes ordered `(task_index,task_identity,taskSpec,plannerVersion,policyVersion,codecVersion)` child evidence plus header identity/count/P using `merlink.sf06.plan.v2\0` / `sf06:plan:v2:`. Those version tags are stored **in each child `evidence_json`**, not standalone header columns, and the manifest can be reconstructed after restart. `parallel_limit` is the sole additional header field needed to verify the frozen P instead of guessing the current runtime configuration. No manifest table or client request ID is necessary. No original LLM bytes are persisted merely to compare responses: an authenticated **canonical effect** may conflict; distinct responses with the same effect are not distinguishable.

`verify_historical_round` is a **proposed** read-only internal operation. Reconstruct S0 from sealed version, exact child indices and manifest/digests, replay versioned pure patches S0→Sn, compare each pre/post hash and input/output fingerprint, compare final canonical bytes against optional version, verify required artifact hash and lineage; return separate `integrity=Verified|Corrupt|Indeterminate/UnsupportedCodec`, `authorization=Attested|Unknown` and `applicability=Applicable|SupersededByProvenDownstream|BranchRevertedByRestore|HeadAdvancedUnproven|BaselineUnavailable`. It uses no RAM LLM response, network, old policy evaluator, external tool, temporary report or audit message. A committed header attests authorization under trusted writer but does not independently re-evaluate it. `seal_or_retry_round` looks up identity **and** seal key before OCC: same committed plan/baseline returns verified historical result without new write **only if** applicable for skip; conflict in intent/plan/base/authenticated effect is structured; restore-diverged or advanced head is historical but not automatically skippable. Only new round demands head==sealed baseline and seals TX-04. Missing/unsupported evidence fails closed. SQL hash verification is corruption detection, not a MAC or cryptographic proof of authorization. Versioned Phase-3 input artifact is required to recompute `world_write` fingerprint from durable data; the trusted writer attests the merger result rather than recovery executing a historical merger.

### Codec, SQLite and zero-net

Architecture report GV-10:545 rejected parent-delete-before-set-null despite its own atomic clone rule §7:501–516. B+ now validates preconditions against S_before, composes complete candidate on clone, checks **final** invariants/byte equality, and rejects whole patch on failure. Serialization has deterministic canonical path/tag order but **no universal operational total order**; independent set-null reference and delete may serialize either way and still produce same valid final state. Same-path writes and field update beneath deleted entity conflict; parent+child insert/counter or scene delete+cascade may be valid as a group. Canonical-state equality excludes `meta.updated_at`, includes provenance/counters/semantic array order and normalized optional TrackedField; hash equality alone is not a logical proof of byte equality. No tool/LLM fallback on codec failure. Spec golden vectors in [BE §6.4.7](../../business/be-core.md#L1532-L1533) are **not runtime PASS**.

Audit:132–143 demonstrates that child `CHECK task_index>=0` does **not** enforce `task_index<parent.task_count`; RFC RC-05:319 is historical false proof, superseded by DBML/BE contract. SQLite enforces nonnegative index, uniqueness, JSON syntax, parent FK and child→parent composite draft/run/generation/base FK, header positive N/P and zero-net hash relation. Backend precommit and recovery enforce index<N, exact `{0..N−1}`, N<=frozen P, manifests, hashes and evidence. Header is immutable **by backend protocol**, not by SQL trigger against arbitrary writer. `Sn≡S0` still creates header+N evidence receipts but no Draft Version, keeping A/B telemetry. No `CHECK N<=6`; runtime default P is not a DB bound.
